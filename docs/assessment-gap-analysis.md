# Assessment requirements and implementation

Source: [CWT X Sentiment Price Prediction Agent assignment](assignment.pdf), pages 1–2.
The earlier project implemented general text sentiment only. The assignment asks
for an asset-price forecasting research pipeline. The implementation below adds
that missing workflow while preserving the text sentiment API.

## Forecast convention

The PDF does not define bar duration or whether period n has already closed.
This implementation uses daily bars and defines n as the first not-yet-completed
exchange session following the last observed price bar. n+0 through n+5 are six
actual forecasts, one through six sessions ahead. It reports the observed close
separately. This avoids presenting an already observed n+0 price as a prediction.

## Research constraints

- The same raw close basis is used for returns and output prices. Corporate
  actions must be reviewed; suspicious large moves are flagged.
- Historical posts are assumed available at their creation times. Retrospective
  scrapes may omit deleted posts or contain edited text. This cannot establish a
  perfect point-in-time archive, and reports disclose that limitation.
- Likes, reposts, views and followers are retained, but not used as historical
  features because their current values were not available at old prediction times.
- Tavily news complements the current outlook. It is never backfilled into old
  feature rows or used as an extra price-model input.
- The price model is fixed Ridge regression with training-fold scaling. There is
  no random split, in-sample performance reporting, or test-set hyperparameter tuning.
- A fixed finance-augmented lexicon supplies X scores. A stronger independently
  validated text model can replace it later; the six-example text API fallback
  model is deliberately not used in this forecasting experiment.
- Demo data demonstrates functionality only. Importing the demo snapshots preserves
  the synthetic marker. No demo performance is claimed as market performance.

## Submission checklist

1. Install dependencies and run `python -m pytest`.
2. Configure `.env` locally with the chosen Apify actors and Apify/Tavily credentials.
3. Run the CLI with `--live`, the chosen ticker and relevant keywords.
4. Inspect `manifest.json` coverage warnings; resolve capped or insufficient history
   before treating the dataset as a complete 180-day assessment sample.
5. Review `evaluation.md`, `sentiment_summary.pdf`, charts and out-of-sample CSVs.
6. Include the repository URL and selected report artifacts with the submission.
   Supply credentials privately, never commit them to the repository.
7. The assignment mentions Exa in the submission wording but specifies Tavily for
   news. This implementation uses Tavily; no Exa integration/token is necessary
   unless the reviewer separately requests Exa as a source.

## Connector references

The integrations follow [Apify actor execution and dataset retrieval](https://docs.apify.com/api/v2),
[the X actor input schema](https://apify.com/apidojo/tweet-scraper/input-schema),
[the configured price actor's documented daily output](https://github.com/logiover/yahoo-finance-scraper),
and [Tavily's search endpoint](https://docs.tavily.com/documentation/api-reference/endpoint/search).
Market-session handling uses [exchange_calendars](https://github.com/gerrymanoim/exchange_calendars).
These external services and actors were not executed against a real account during implementation.
